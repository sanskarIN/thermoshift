# Release Evidence

A ThermoShift release is evidence-driven. This document defines what must be recorded before a release candidate is described as verified and before a stable tag is created.

## Candidate identity

Record:

- candidate version;
- Git commit SHA;
- source branch/pull request;
- date of verification;
- verifier/environment for platform-specific checks.

Do not reuse evidence from an older commit after the candidate changes.

## Source and repository integrity

Required evidence:

- `npm run check:versions` passes;
- `npm run check:desktop-config` passes;
- `npm run check:docs` passes;
- no unfinished blocker/critical defect is knowingly left open;
- no secret/signing credential is committed;
- dependency lockfiles exist and were generated by native package-manager tooling before locked/reproducible release claims are made.

## Rust/domain evidence

Record successful results for:

```bash
cargo fmt --all -- --check
cargo test -p thermoshift-core
cargo clippy -p thermoshift-core -p thermoshift-wasm --all-targets -- -D warnings
```

When committed `Cargo.lock` exists, release-sensitive commands should use `--locked`.

## Web/PWA evidence

Record successful results for:

```bash
npm --workspace @thermoshift/web run typecheck
npm --workspace @thermoshift/web run lint
npm --workspace @thermoshift/web run test
npm --workspace @thermoshift/web run build
npm run check:web-budget
npm --workspace @thermoshift/web run e2e
```

The E2E result must come from the real production/WASM-backed app and include the configured axe accessibility checks.

## Screenshot evidence

Real screenshots are release evidence only when captured from a successfully built/running ThermoShift app.

The repository provides:

```bash
npm --workspace @thermoshift/web run screenshots
npm run check:screenshots
```

The expected committed set is:

- onboarding desktop/mobile;
- converter desktop/mobile;
- Settings desktop/mobile;
- About desktop/mobile.

The screenshot verifier checks the exact set, PNG signatures, minimum file sizes, and sane desktop/mobile dimensions. Mockups, manually relabeled images, or empty placeholders must not be called product screenshots.

## Security evidence

Review the current candidate's:

- CodeQL result;
- Gitleaks result;
- RustSec audit result;
- npm audit result;
- dependency-update/security alerts relevant to the candidate.

A local audit is useful additional evidence but does not silently substitute for a failing required hosted check.

## Desktop/platform evidence

For each supported native target, record an unsigned package build on the native platform:

- Windows;
- macOS;
- Linux.

The `Desktop Platform Verification` workflow provides an unsigned CI matrix and uploads native bundle evidence. A successful build on one operating system is not evidence for the other two.

Signing and notarization are separate publication gates. Their credentials remain owner-controlled and outside Git.

## Branding evidence

Verify the desktop bundle has generated platform icon assets derived from the repository's editable ThermoShift logo source. The `Refresh Desktop Icons` workflow is the reproducible generator path. Do not claim platform icon completion until the generated files actually exist in the candidate commit.

## Offline and update evidence

Verify a production PWA can:

- complete conversion after application assets are cached and connectivity is removed;
- preserve local settings/history behavior as documented;
- surface offline state without blocking conversion;
- perform/update-check behavior consistently with Settings documentation when connectivity is available.

Record the browser/device used for manual offline-install evidence when this is part of the release gate.

## Release artifact evidence

For a `vX.Y.Z` candidate, verify:

- source/package version matches the exact tag;
- the release workflow completes its full quality gate;
- the produced web archive is non-empty;
- the SHA-256 checksum file is published alongside it;
- the checksum validates the downloaded archive;
- generated release notes do not claim unsupported platform/security status.
