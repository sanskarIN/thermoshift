# v0.2 product implementation completed in source

## Canonical temperature engine

Executable conversion rules remain in `crates/thermoshift-core`.

Supported scales:

- Celsius;
- Fahrenheit;
- Kelvin;
- Rankine;
- Réaumur;
- Delisle;
- Newton;
- Rømer.

The core includes:

- finite-value validation;
- absolute-zero validation;
- canonical conversion through Kelvin;
- normalized zero-K handling around the validation epsilon;
- reference-point tests;
- all-scale round-trip tests;
- dense 0–5000 K pairwise invariants;
- direction checks, including the reversed Delisle scale.

## Unicode-aware unit parsing

Unit parsing accepts supported names, symbols, aliases, whitespace variants, and uppercase accented forms such as:

- `RÉAUMUR`;
- `RØMER`;
- `°RÉ`;
- `°RØ`.

Unknown input continues to preserve the original value in the domain error.

## Browser persistence

Local persistence uses versioned keys and forgiving recovery for damaged browser cache state:

- `thermoshift.settings.v1`;
- `thermoshift.history.v1`;
- `thermoshift.onboarding.v1`.

Behavior includes:

- safe settings defaults/sanitization;
- supported unit validation;
- finite numeric validation;
- timestamp validation;
- duplicate history ID cleanup for local cache recovery;
- 50-record history retention;
- storage failure handling through the redacted local logging boundary;
- onboarding state stored separately.

## Strict full-data backup/restore

Full backup schema remains independently versioned with `schemaVersion: 1`.

The restore boundary is strict/fail-closed, unlike forgiving local-cache recovery.

The parser rejects before replacing application state:

- inputs above 256 KiB;
- malformed JSON;
- unsupported schema versions;
- invalid/missing export timestamps;
- incomplete or invalid settings;
- invalid/missing history arrays;
- history above 50 records;
- invalid IDs/timestamps/numeric values/units;
- duplicate conversion identifiers.

The UI also rejects oversized files before reading file text.

## First-run onboarding

The accessible onboarding flow explains:

- eight supported scales;
- local-first privacy;
- offline-first use;
- no account requirement;
- local preferences/history behavior.

Users may start converting or open Settings first. Resetting local ThermoShift data restores onboarding.

## Quick Actions and keyboard navigation

Implemented keyboard workflow:

- `Ctrl+K` / `⌘+K` opens Quick Actions after onboarding;
- `Alt+1` Converter;
- `Alt+2` Batch;
- `Alt+3` History;
- `Alt+4` Formulas;
- `Alt+5` Settings;
- `Alt+6` About.

Global page shortcuts do not steal editable control interactions and do not mutate background navigation while modal onboarding/Quick Actions owns interaction.

Page changes synchronize document titles and a polite live-region announcement. Shortcut metadata is exposed with `aria-keyshortcuts`.

## Dialog accessibility

The shared dialog focus hook handles:

- initial focus;
- forward/backward Tab wrapping;
- focus recapture when focus escapes;
- hidden/`aria-hidden` filtering;
- Escape handling where applicable;
- focus restoration.

## Converter and batch safety

Converter UX includes:

- instant conversion;
- physical validation;
- `aria-invalid` semantics;
- save/copy/share feedback;
- safe generic operational failure messages.

Batch conversion includes:

- per-line conversion/errors;
- CSV export;
- 32,768-character input ceiling;
- 1,000-line ceiling before conversion work.

## History

History includes:

- local save;
- search;
- from/to filters;
- individual delete;
- clear;
- undo;
- JSON export;
- persistence across reload.

## Reference and formula education surfaces

Reference cards allow the user to choose the display scale.

Formula pages contain educational equations and derivation notes while executable conversion behavior remains owned by Rust.

## PWA and update behavior

The web app is installable/offline-capable through the Vite PWA/service-worker path.

Settings exposes application version/update controls without making conversion depend on network availability.

Raw update/startup errors are not echoed directly to users; detailed operational state stays behind the redacted local diagnostic boundary.

## Local structured diagnostics

Structured diagnostics are local-only and sanitize secret/session/contact/content/value-shaped metadata.

Error objects are reduced to safe type information instead of dumping raw error messages into structured metadata.

## Export/browser capability safety

Clipboard, share, and download paths now:

- keep rejected operational details out of user-facing copy;
- treat native share cancellation as an ordinary cancellation;
- preserve clipboard fallback behavior where native share is unavailable;
- remove temporary download anchors;
- schedule object URL revocation even when dispatch fails;
- log failures only through the redacted local boundary.
