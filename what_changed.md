## Product implementation present

ThermoShift uses one canonical Rust temperature engine exposed to the browser through WebAssembly and reused by the Tauri desktop target.

Supported scales:

- Celsius;
- Fahrenheit;
- Kelvin;
- Rankine;
- Réaumur;
- Delisle;
- Newton;
- Rømer.

Core/domain behavior includes finite-number validation, absolute-zero enforcement, canonical conversion through Kelvin, Unicode-aware scale parsing, canonical reference tests, all-scale round trips, and dense pairwise invariants.

The React/PWA product includes:

- instant conversion;
- configurable precision and rounding;
- batch conversion with CSV export and bounded input;
- local history with search/filter/delete/clear/undo;
- full JSON backup/restore with strict validation and a 256 KiB input ceiling;
- reference cards and formula education;
- first-run onboarding;
- Quick Actions and keyboard navigation;
- local-only settings and persistence;
- light/dark/system themes, high contrast, and reduced motion;
- PWA install/offline/update behavior;
- copy/share/export flows;
- About/support surfaces;
- responsive accessible layouts.

## Final correctness/security hardening already present

The final audit before the 2.8.2 version migration fixed and documented several release-quality defects:

- decimal `half-up` presentation rounding now correctly handles binary floating-point edges such as `±1.005`;
- formatting and rounding share the same 0–12 precision clamp;
- huge finite values are preserved when presentation-only decimal shifting would overflow;
- regression tests cover rounding/truncation/precision/magnitude edges;
- clipboard/share/download failures use generic user-facing feedback and redacted local diagnostics;
- backup restore treats imported data as untrusted and fails closed before state replacement;
- dialogs contain/recapture/restore focus;
- page changes synchronize document titles and accessible live announcements;
- batch conversion is bounded before conversion work;
- generated lockfile/icon/screenshot workflows refuse to rebase stale generated evidence onto a newer branch head;
- release provenance requires a full 40- or 64-character hexadecimal Git object ID and a non-empty single-line ref;
- release provenance verifies archive checksums and records SHA-256 evidence digests.
